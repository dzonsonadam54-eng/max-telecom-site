# Подключение 1С:Управление торговлей к сайту MAX Telecom

Сайт: https://max-telecom-site.vercel.app (хостинг Vercel, код в этом репозитории).

## Что показывает сайт

В окне каждого раздела продукции — список позиций:

| Поле | Откуда в 1С |
|---|---|
| Наименование, артикул | Справочник «Номенклатура» |
| Раздел сайта | Группа номенклатуры (родитель) или слова в названии |
| Статус «В наличии / Мало / Под заказ» | Регистр накопления «Товары на складах»: `ВНаличии − ВРезервеСоСклада` |
| Розничная цена | Регистр сведений «Цены номенклатуры», вид цены «Розничная» |

**Какие позиции попадают на сайт:** товары (тип номенклатуры «Товар», без услуг), не помеченные
на удаление, **у которых установлена розничная цена**. Это правило — рычаг для владельца:
нужна позиция на сайте — ставит ей розничную цену; не нужна — не ставит. Подробно для заказчика:
[`kak-dobavit-tovar-na-sajt.md`](kak-dobavit-tovar-na-sajt.md).

**Точное количество на сайт не передаётся** — только статус. Порог «мало» задаётся в
`max-telecom-site/api/_lib/config.json` (`lowThreshold`): по умолчанию меньше 500 м, меньше 5 шт.
Закупочные цены, контрагенты и документы сайт не получает ни в одной из схем.

Пока 1С не подключена, блок наличия на сайте скрыт. Посмотреть, как он выглядит:
https://max-telecom-site.vercel.app/?demo

## Какую схему выбрать

| Где стоит 1С | Схема | Что нужно открыть наружу |
|---|---|---|
| Сервер или ПК в офисе | **Б — 1С отправляет данные на сайт** (рекомендуется) | Ничего. 1С сама делает исходящий HTTPS-запрос |
| Облако (1С:Фреш, Scloud, аренда) | **А — сайт забирает данные по OData** | Опубликованный по HTTPS OData-интерфейс |

Схема Б безопаснее для офисного сервера: в базу никто не заходит снаружи, порты не открываются.

---

## Общий шаг для обеих схем: пользователь только на чтение

1. В 1С создайте пользователя, например `site_reader`, со сложным паролем (от 16 символов).
2. Дайте ему права **только на чтение**: справочник «Номенклатура», справочник «Упаковки единиц измерения»,
   регистр «Товары на складах», регистр «Цены номенклатуры». Без интерактивного входа.

## Схема А — сайт забирает данные по OData (1С в облаке)

### 1. Включить стандартный интерфейс OData

1. Конфигуратор → **Администрирование → Публикация на веб-сервере**. Отметьте
   **«Публиковать стандартный интерфейс OData»**. Публикация должна быть доступна по **HTTPS**.
   В облачных сервисах 1С публикацию OData обычно включает поддержка сервиса по запросу.
2. В режиме 1С:Предприятие: **Все функции → Обработки → «Настройка автоматического REST-сервиса»**
   (в некоторых версиях — «Настройка стандартного интерфейса OData»). Отметьте только:
   - `Справочник.Номенклатура`
   - `Справочник.УпаковкиЕдиницыИзмерения`
   - `Справочник.ВидыЦен` (нужен один раз, чтобы узнать GUID розничной цены)
   - `РегистрНакопления.ТоварыНаСкладах`
   - `РегистрСведений.ЦеныНоменклатуры25` (УТ 11.5 и новее) или `РегистрСведений.ЦеныНоменклатуры` (УТ 11.4)

### 2. Проверить из браузера

```
https://<адрес>/<база>/odata/standard.odata/Catalog_Номенклатура?$top=3&$format=json
https://<адрес>/<база>/odata/standard.odata/AccumulationRegister_ТоварыНаСкладах/Balance()?$format=json
```
Браузер спросит логин и пароль `site_reader` и должен вернуть JSON.

### 3. Узнать GUID вида цены «Розничная»

```
https://<адрес>/<база>/odata/standard.odata/Catalog_ВидыЦен?$select=Ref_Key,Description&$format=json
```
Скопируйте `Ref_Key` строки «Розничная».

### 4. Переменные окружения в Vercel

Vercel → проект → **Settings → Environment Variables** (Production):

| Переменная | Значение |
|---|---|
| `ODATA_URL` | `https://<адрес>/<база>/odata/standard.odata` |
| `ODATA_USER` | `site_reader` |
| `ODATA_PASS` | пароль |
| `PRICE_TYPE_KEY` | GUID вида цены «Розничная» |
| `ODATA_WAREHOUSE_KEY` | необязательно: GUID склада, если показывать остаток только одного склада |

После сохранения — **Deployments → ⋯ → Redeploy**. Сайт обращается к 1С не чаще раза в 15 минут:
ответ кэшируется на стороне Vercel.

**Рекомендуется:** подключить и хранилище — Vercel → **Storage → Create → Upstash (Redis)**,
бесплатный план, подключить к проекту (появятся `KV_REST_API_URL` и `KV_REST_API_TOKEN`).
Тогда сайт сохраняет последние удачные данные и, если облачная 1С временно недоступна
(техработы, сбой, сменили пароль), показывает их вместо того, чтобы скрыть блок наличия.
`STOCK_PUSH_TOKEN` для этой схемы не нужен.

Рекомендуется ограничить доступ к публикации OData по IP или хотя бы по сложному паролю
и не использовать этого пользователя ни для чего другого.

## Схема Б — 1С отправляет данные на сайт (1С в офисе)

### 1. Хранилище на стороне сайта (один раз, в Vercel)

1. Vercel → проект → **Storage → Create → Upstash (Redis)**, бесплатный план, подключить к проекту.
   Vercel сам добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN`.
2. **Settings → Environment Variables** → добавить `STOCK_PUSH_TOKEN` — случайная строка
   **не короче 24 символов** (например, сгенерированная менеджером паролей). Этот же ключ вписывается в 1С.
3. **Redeploy**.

не в коде.

Когда сайт переедет на свой домен (например, `maxtelecom.kz`), замените хост в `HTTPСоединение`.

## Сопоставление групп 1С с разделами сайта

Файл `max-telecom-site/api/_lib/config.json`:

- `groups` — точное имя группы в 1С → раздел сайта. Например:
  `"Кабель ОКСН": "aerial"`, `"Патч-корды и пигтейлы": "patch"`.
- `keywords` — запасной вариант: если группа не указана, раздел определяется по словам
  в названии группы или товара («самонесущ» → самонесущий кабель, «муфт» → муфты и т.д.).

Разделы сайта: `indoor` внутриобъектовый, `dist` распределительный, `ftth` FTTH, `drop` дроп-кабель,
`aerial` самонесущий, `duct` в канализацию, `ground` в грунт, `closure` муфты, `clamp` арматура,
`splice` сварка, `patch` патч-корды и пигтейлы, `split` разветвители, `odf` кроссы, `copper` медь.
Позиции, которые не попали ни в один раздел, всё равно видны на сайте в блоке **«Каталог и наличие»**
под названием своей группы из 1С. Поэтому новые виды товаров появляются на сайте без доработок;
сопоставление нужно только чтобы они попали ещё и в окно соответствующего раздела.

## Проверка после подключения

- `https://max-telecom-site.vercel.app/api/stock` — должен вернуть `"configured": true` и список позиций
  **без** поля количества.
- На сайте: появится блок «Каталог и наличие» с поиском; в окне раздела продукции — «Наличие и цены».
